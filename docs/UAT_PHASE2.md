## Defects corrected during UAT

1. Sources table labeled the latest run's extracted count as persisted “Records”; now labeled “Last extracted” with a clarifying tooltip.
2. Sidebar and topbar claimed the engine was ready while offline; they now show connecting/unavailable states and disable new-source action when unavailable.
3. Shared resource data could remain visible after a failed refresh; failed requests clear it.
4. Record search scope was ambiguous; the UI now states that search covers the current 50-record page.
5. Drawers lacked focus control; they now focus on open, trap Tab, close with Escape, and restore trigger focus.
6. SQLite returned naive UTC timestamps, which the browser interpreted as local time; the UI now treats timezone-free API timestamps as UTC.
7. Vite proxy failures produced a generic error; an unavailable API now has a connection-specific message.
8. The sticky mobile execution action obscured status; at 390px the table shows run, status, and detail action together.
9. Vite's proxy target can be overridden through `SCRAPEFLOW_API_TARGET` for isolated local verification.

## Remaining limitations and recommendation

- Search is deliberately limited to the loaded records page; there is no server search endpoint.
- The dashboard loads all source and run pages sequentially. This was responsive with four sources and seven runs; high-volume performance was not load-tested.
- At laptop widths, wide record and execution tables use horizontal scrolling. Mobile execution counters and source name are available in the detail drawer rather than the compact table.
- The browser tool allowed real visual inspection but did not expose a supported way to save captures into the repository; screenshot files are unavailable.
- Public example sites are external and their future availability/content may change.
